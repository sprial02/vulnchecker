⑦ 인프라 점검

Start.cmd → ⑦ 인프라 점검에서 Linux 및 Windows 서버를 등록하고 보안 설정을 점검합니다. 별도 실행 창이나 YAML 편집 없이 UI에서 설치, 연결 확인, 실행, 결과 조회와 실패 서버 재실행을 진행합니다. 마지막으로 선택한 탭과 테마는 다음 실행에도 유지됩니다.

처음 사용하는 순서

  1. 기본 Kali 환경이 없으면 ① 설치에서 준비합니다. ⑦ 탭의 Ansible 설치 / 확인을 눌러 Ansible Core 및 Windows 접속 구성 요소를 설치합니다. Kali 배포판/사용자는 기존 설정을 사용합니다.
  2. 새 서버 → 서버 이름, 주소, 종류, 계정과 암호를 입력하고 서버 저장을 누릅니다. 여러 서버를 각각 등록할 수 있습니다.
  3. 목록에서 서버를 선택하고 접속 / 권한 확인을 누릅니다. Linux는 SSH 및 sudo root 권한, Windows는 WinRM/PSRP 및 관리자 토큰을 확인합니다.
  4. 선택 서버 점검 또는 전체 서버 점검을 누릅니다. 여러 서버 선택은 Ctrl/Shift를 사용합니다. 전체 점검은 ‘전체 점검에 포함’이 켜진 서버에 적용됩니다.
  5. 점검 결과 / 재실행에서 실행 이력을 선택해 서버별 양호·취약·수동·해당 없음·실패 사유를 확인합니다. 결과 폴더 열기로 원본 JSON/TXT와 항목별 실행 로그가 들어 있는 압축 증적을 확인합니다.

서버 설정

입력 항목설명
서버 이름 / 주소이름은 고유한 영문·숫자·점·밑줄·하이픈입니다. 주소에는 서버 IP 또는 호스트 이름을 입력합니다.
Linux · Debian / RedHatOS 계열에 맞게 선택합니다. SSH 기본 포트는 22이며 대상에 Python 3, bash, tar와 필요한 OS 명령이 있어야 합니다. root가 아닌 계정은 sudo 권한이 필요합니다.
Windows · WinRM / PSRPWindows Server 2019 이상, PowerShell 5.1, 원격 관리자 권한이 필요합니다. HTTPS 기본 5986, HTTP 기본 5985입니다. NTLM 메시지 암호화를 적용하고 HTTPS 인증서는 검증합니다. 서버의 WinRM/방화벽/UAC 설정은 변경하지 않습니다.
접속 암호 / sudo 암호입력란은 마스킹되고 저장값은 Windows 현재 계정으로 암호화됩니다. 이미 저장한 서버에서 빈 입력란은 기존 암호를 유지합니다. sudo 암호를 등록하지 않으면 접속 암호를 사용합니다. 저장 뒤 입력란은 비웁니다. 접속 암호를 삭제하려면 서버 항목을 삭제하고 다시 등록하세요.
SSH 키암호 대신 키를 쓰려면 Kali의 절대 경로 또는 ~/ 경로를 입력합니다. 키 파일은 Kali에서 읽을 수 있어야 합니다. Windows 파일 선택 경로가 아닙니다.
최초 SSH 키 등록처음 연결하는 승인된 서버의 키를 전용 known_hosts에 등록합니다. 이후 키 검증을 유지하며 이미 등록된 키가 바뀌면 접속을 차단합니다. 기존 검증 환경의 호스트 키는 재사용합니다.
제한(초)항목별 실행 제한입니다. 기본 90초이며 전체 파일 검색이 긴 서버는 300초 등으로 늘릴 수 있습니다. 시간 초과는 실행 실패로 기록됩니다.
기존 서버이전에 별도 Ansible로 검증한 서버를 UI로 가져옵니다. 새 PC에서는 직접 등록하세요. 가져온 암호도 Windows 계정으로 암호화됩니다.

실패 서버만 다시 실행

점검 이력을 선택하고 실패 서버 전체 재실행을 누르면 그 실행에서 실패한 서버만 재점검합니다. 특정 서버만 다시 실행하려면 표의 ‘선택’ 칸을 체크하고 선택 실패 서버 재실행을 누르세요. 정상 서버를 체크해도 실패 서버 재실행에는 포함하지 않습니다. 선택한 서버의 전체 항목을 다시 실행하고 새 이력으로 보관합니다.

취약 발견과 실행 실패는 구분합니다. 취약은 결과가 생성되어 VULNERABLE로 판정된 상태입니다. 실행 실패는 접속/권한 오류, 비정상 종료, 시간 초과 또는 JSON 누락입니다. 수동 판정은 원본 증적을 검토해야 합니다.

점검 범위와 알려진 원본 문제

KISA-CIIP-2026 저장소의 고정 커밋 d081fc1e75a2be207eb2e57632e5e5f398e273b1을 사용합니다. Linux 67개, Windows 64개 항목을 실행하며 보안 설정 자동 조치는 하지 않습니다. 원본 점검 로직은 유지합니다.

실제 Kali 검증에서 Debian U-64는 보안 업데이트 문자열이 없으면 원본의 grep/pipefail 처리로 결과 저장 전에 종료하는 문제가 확인됐습니다. UI에 실행 실패로 표시하며 해당 항목의 패치 정책과 적용 이력은 수동 확인해야 합니다. U-25의 파일 검색은 서버에 따라 기본 90초를 초과할 수 있습니다.

저장과 보관

Windows는 사용자별 runtime에 암호화된 서버 설정과 infra-runs 결과를 보관합니다. Kali는 사용자 홈의 ~/.local/share/vulnchecker-infra에서 전용 Python 환경과 UI 전용 Vault를 사용합니다. 기존 CLI 인벤토리와 다른 도구의 Python 환경은 유지합니다. 서버 삭제는 UI 등록 정보만 삭제하며 과거 점검 증적은 유지합니다. 변경 내용은 다음 실행 시 Kali 인벤토리에 반영됩니다. 대상 임시 폴더 kisa-infra-*는 수동 확인을 위해 유지하므로 보존 정책에 따라 관리하세요.

배포 ZIP에는 서버 암호, 실제 인벤토리, Vault, 실행 결과, 원본 다운로드 및 캐시를 포함하지 않습니다. 소스 라이선스는 원본 AGPL-3.0을 참고하세요.
