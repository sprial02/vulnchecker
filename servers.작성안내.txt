인프라 점검 대상 CSV 작성 안내

한 행에 서버 한 대를 작성하고 UTF-8 CSV로 저장하세요. 열 이름을 변경하지 마세요.

[필수]
Host: 접속할 IP 또는 호스트 주소. 예: 192.0.2.10
User: SSH/Windows 원격 접속 계정. 예: audit 또는 DOMAIN\audit
Connection: ssh / winrm / psrp 중 하나
Platform: SSH는 Auto / Debian / RedHat / AIX / HP-UX / Solaris, Windows는 Windows
Port: 실제 접속 포트(1~65535). 기본 SSH 22, Windows HTTPS 5986
인증: 새로 등록하는 활성 서버의 SSH는 Password 또는 KeyFile, Windows는 Password 필수

[선택]
Alias: 서버 이름. 없으면 빈칸으로 두세요. Host의 IPv4 주소 또는 호스트 이름을 사용합니다.
       Alias에 IP를 직접 입력해도 됩니다. IPv6 주소는 내부 이름에서 ip6- 접두사와 하이픈으로 변환합니다.
Password: 접속 암호. 기존 서버 갱신 시 빈칸이면 저장 암호를 유지합니다.
BecomePassword: sudo 암호. 빈칸이면 접속 암호를 사용합니다.
KeyFile: SSH 개인 키를 사용하는 경우 점검 환경 Kali의 기존 절대 경로
Protocol: Windows https 권장. 기본 https. HTTP를 사용하는 경우 실제 정책/포트 확인
Timeout: 점검 항목별 제한 시간(10~3600초), 기본 90초
Enabled: true(점검 포함, 기본값) / false(목록만 등록하고 실행 제외)
TrustNewHostKey: 기존 호환 열. SSH 최초 키는 accept-new로 저장하고 변경된 키는 차단합니다.

활성 서버에 인증 정보가 없거나 필수 값이 비어 있으면 등록하지 않고 행 번호와 이유를 표시합니다.
한 행이라도 오류가 있으면 전체 CSV 등록을 취소하여 기존 목록을 보존합니다.
같은 Alias가 이미 등록돼 있으면 해당 서버 설정을 갱신합니다. 한 CSV 안에 같은 Alias를 중복 작성하지 마세요.
이름 생략 시 같은 IP가 두 행 이상 나오지 않도록 확인하세요. OS/WAS/DB 점검 구성은 등록 후 별도 지정합니다.

예시(실제 암호로 바꿔 작성; 아래 주소는 설명용):
Alias,Host,User,Connection,Platform,Port,Password
,192.0.2.10,audit,ssh,Auto,22,접속암호
192.0.2.20,192.0.2.20,DOMAIN\audit,psrp,Windows,5986,접속암호

CSV에는 암호가 평문으로 들어갈 수 있습니다. 승인된 안전한 전달 경로를 사용하고 파일을 별도로 보호하세요.
점검 중 연결 실패·시간 초과 서버는 실패로 남기고 다른 서버는 계속 진행합니다.
failures.csv에는 IP/포트, 실패 단계, 사유 분류와 담당자 확인 요청 사항이 기록됩니다.
사유는 관측된 오류의 분류이며 라우터·방화벽·서버 중 정확한 원인 확정에는 담당자 확인이 필요합니다.
